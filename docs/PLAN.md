# 수업 사이드바 — 설계 계획서 v0.3

> 작성일 2026-11-21 · 상태: **시안 검토 중 (제작 전)**
> 정해진 것: 윈도우와 맥 모두 지원 · 듀얼 모니터(교사 화면 + 학생 화면) 기본 고려 · 설치형 프로그램 하나 (확장 프로그램 없음) · 테스트용 윈도우 PC 있음 · 맥과 윈도우의 Claude가 GitHub 비공개 저장소로 협업
> 함께 보는 파일: `design/prototype.html` (클릭해 볼 수 있는 UI 시안)
>
> **지금까지 바뀐 점**
> - v0.2: 한 창 안에서 모든 자료를 보여주는 방식을 버리고, 자료는 원래 프로그램이 열고 사이드바가 창을 관리하는 **수업 사이드바 방식**으로 바꿨다. **화면 분할**, **수업 폴더 단위 관리(클라우드 폴더로 윈도우↔맥 편집)**, **수업 꾸러미(.zip)**를 넣었다.
> - v0.3: **크롬 확장 프로그램을 빼고 설치형 프로그램 하나로 통일**했다 (0장, 4.1). **듀얼 모니터**를 기본으로 고려하도록 6장을 새로 넣었다.

수업 사이드바는 화면 왼쪽에 숨어 있다가 나타나는 목록 창이다. 수업 흐름대로 자료를 모아 두고, 수업 중에는 이 목록 하나로 한글·파워포인트·브라우저 등을 열고, 앞으로 가져오고, 나란히 배치하고, 닫는다. 수업에 쓰는 모든 것은 수업 폴더 하나에 정리된다.

## 0. 프로그램 형태

- **설치형 데스크톱 프로그램 하나**다. 윈도우는 `.exe`, 맥은 `.dmg`로 설치한다. 확장 프로그램이나 웹사이트는 따로 없다.
- 학교 PC용으로 같은 프로그램의 **설치 없이 실행하는 버전**(portable .exe)도 만든다. 기능은 같고 설치만 하지 않는다.
- v0.2까지는 크롬 탭을 고르기 위한 크롬 확장 프로그램을 함께 계획했지만 뺐다. 웹 자료를 탭 대신 **자료마다 새 브라우저 창**으로 열면 한글·PPT 창과 똑같은 방식으로 찾고, 앞으로 가져오고, 배치하고, 닫을 수 있기 때문이다 (4.1).
- 그 덕분에 크롬뿐 아니라 엣지·웨일 같은 다른 브라우저도 쓸 수 있다.

## 1. 검토: 차선책(사이드바)을 기본으로 하는 것이 맞는가

**결론: 맞다.** 수업 사이드바 방식으로 만들고, 앱 안에서 자료를 직접 보여주는 기능은 넣지 않는다.

### 1.1 두 방식 비교

| 기준 | 한 창 통합형 (v0.1) | 수업 사이드바형 (채택) |
|---|---|---|
| 자료를 보여주는 주체 | 우리 앱 (웹 화면, PDF 뷰어, 미디어, 문서 변환을 직접 처리) | 한글·파워포인트·엑셀·브라우저 등 검증된 원래 프로그램 |
| 표시 품질 | PPT 애니메이션·한글 서식은 재현 불가 | 원래 프로그램 그대로 |
| 구글·캔바 로그인 | 내장 브라우저 로그인 차단 위험 | 평소 쓰는 브라우저라 문제 없음 |
| 하나가 멈추면 | 앱 전체가 영향받을 수 있음 | 그 프로그램만 멈추고 사이드바·나머지는 그대로 |
| 만들 양 | 많음 (종류별 뷰어, 탭, 분할, 변환) | 적음 (열기·찾기·앞으로·배치·닫기) |
| 메모리 | 앱 하나가 많이 씀 | 각 프로그램이 나눠 씀, 사이드바는 가벼움 |
| 창 전환 속도 | 빠름 | 미리 열어 두면 빠름 (처음 켤 때만 느림) |
| 확대·포인터·캡처 핀·스포트라이트·녹화 | 가능 | 똑같이 가능 (화면 전체에 동작) |
| 필요 조건 | 없음 | 수업 PC에 해당 프로그램 설치, 맥은 접근성 권한 |

### 1.2 사이드바 방식을 고르는 이유

1. **고장 나는 곳이 줄어든다.** 자료를 그리는 어려운 일은 오래 검증된 프로그램이 맡고, 사이드바는 창을 다루는 일만 한다. 우리가 만드는 코드가 적을수록 수업 중 사고도 적다.
2. **원래 문제를 정확히 해결한다.** 문제는 "창이 수십 개라 찾느라 시간이 간다"였다. 창이 몇 개든 사이드바가 유일한 리모컨이 되면 찾을 일이 없다.
3. **아낀 개발 시간을 위험한 곳에 쓴다.** 창을 정확히 찾고 앞으로 가져오는 일, 듀얼 모니터, 장시간 녹화 안정성에 집중한다.

### 1.3 사이드바 방식의 약점과 대응

| 약점 | 대응 |
|---|---|
| 프로그램을 처음 켤 때 느림 (PPT 3~5초) | **"수업 시작 · 모두 미리 열기"**: 수업 직전에 모든 자료를 열어 두고, 수업 중 클릭은 앞으로 가져오기만 (0.3초 이내) |
| 다른 프로그램 창을 정확히 찾아야 함 | 새로 생긴 창을 바로 연결하고, 창 번호로 계속 추적 (4.1). 끝내 못 찾으면 열린 창 목록에서 직접 연결. 0단계 PoC에서 집중 검증 |
| 웹 자료가 탭이 아니라 창으로 열림 | 사이드바로 전환하므로 창이 많아도 찾을 일이 없고, 화면 분할 때 탭을 떼어낼 필요도 없다. 다만 탭 하나만 골라 닫는 기능은 없다 (창 단위) |
| 수업 PC에 프로그램이 있어야 함 | 사전 점검에서 확인, 없으면 대안 안내 (한글 뷰어, PDF·그림·영상은 브라우저) |
| 맥은 "손쉬운 사용" 권한 필요 | 첫 실행 때 안내 화면 |
| 창이 여러 개라 어수선함 | 사이드바로만 전환, "다른 창 숨기기", 화면 분할 |

### 1.4 그래도 앱으로 만드는 이유

웹페이지나 브라우저 확장 프로그램만으로는 한글·PPT 창을 앞으로 가져오거나 배치할 수 없고, 화면 위 도구와 녹화, 듀얼 모니터 제어도 제한된다. 그래서 설치형 데스크톱 프로그램으로 만든다.

- 종류마다 여는 프로그램은 설정에서 바꿀 수 있다. 어느 브라우저를 쓸지도 설정에서 고른다 (기본: 이 PC의 기본 브라우저).
- 로컬 파일(PDF·그림·음악·영상)을 브라우저로 열 때는 사이드바가 띄우는 **내부 주소**(`http://127.0.0.1:포트/무작위토큰/파일`)로 제공한다. `file://` 경로를 넘기면 맥의 폴더 보호 때문에 "바탕화면 폴더의 파일에 접근하려고 합니다" 권한 창이 뜨고, 학교 관리 브라우저는 `file://`을 막기도 한다 (맥 기술 검증에서 확인). 내부 주소는 이 PC 안에서만 열리고, 토큰이 맞아야 하며, 수업 폴더 밖 파일은 주지 않는다.

## 4. 창 관리 (사이드바의 핵심)

### 4.1 열기와 연결
- **원래 프로그램 파일**: 수업 폴더 안 파일만 연다. 연 직후 10초 동안 해당 프로그램(POWERPNT.EXE, Hwp.exe, EXCEL.EXE 등)의 창 중 제목에 파일 이름이 들어간 창을 찾아 자료와 연결한다. 오피스는 여러 문서를 한 프로세스가 열기 때문에 프로세스 번호가 아닌 창으로 구분한다.
- **웹 자료**: 브라우저에 "새 창으로 열기"를 요청한다 (윈도우 `chrome.exe --new-window <주소>`, 맥 `open -na "Google Chrome" --args --new-window <주소>`, 엣지·웨일도 같은 방식). 열기 직전과 직후의 브라우저 창 목록을 비교해 **새로 생긴 창**을 자료와 연결한다. 그 뒤로는 창 제목이 바뀌어도 창 번호(윈도우 HWND, 맥 창 ID)로 계속 추적한다.
  - 맥은 실행 파일을 직접 부르지 않고 LaunchServices(`open`)로 연다. 직접 부르면 부른 쪽의 제한을 물려받아 브라우저가 제대로 뜨지 않을 수 있다 (맥 검증에서 확인).
  - 평소 쓰는 브라우저 프로필 그대로라 구글·캔바 로그인이 유지된다.
  - 선택: "주소창 없이 깔끔하게"(앱 모드 `--app=<주소>`) — 발표할 때 탭·주소창 없이 내용만 보인다.
  - 브라우저가 꺼져 있을 때 처음 열면 이전에 열려 있던 창들이 함께 복원될 수 있다. 이때는 주소가 맞는 창을 고르고, "모두 미리 열기"는 브라우저부터 띄워 둔다 (PoC 확인).
  - 사용자가 그 창에서 새 탭을 열어도 창 단위로 관리되므로 문제 없다.
- 연결이 끊기면(창이 다시 만들어짐 등) 다시 찾고, 그래도 없으면 사이드바에 "창 다시 연결" 버튼을 보여 준다.

### 4.2 앞으로 가져오기
- 윈도우: 최소화돼 있으면 복원 후 `SetForegroundWindow`. 사용자가 방금 사이드바를 클릭했으므로 윈도우의 앞 창 제한에 걸리지 않는다.
- 맥: 앱 활성화 + 접근성 API `AXRaise`.
- 앞으로 가져온 창은 테두리를 잠깐 반짝여 어느 창이 왔는지 바로 보이게 한다.

### 4.3 현재 화면 강조
앞 창을 0.3초마다 확인해 사이드바 강조를 옮긴다. 사용자가 Alt+Tab이나 작업 표시줄로 직접 바꿔도 따라간다.

### 4.4 닫기
정상 종료 요청만 보낸다(윈도우 `WM_CLOSE`, 맥 닫기 버튼). 저장하지 않은 문서는 원래 프로그램이 저장 여부를 묻는다. 강제 종료는 하지 않는다.

프로그램에 **확인·로그인 창(모달)**이 떠 있으면 닫기 요청이 무시된다 (맥 검증: 엣지에 학교 계정 로그인 창이 떠 있어 창이 닫히지 않음). 닫기 요청 뒤 창이 남아 있으면 사이드바는 그 항목에 "답을 기다리는 창이 있습니다"를 표시하고, 그 확인 창을 앞으로 가져와 선생님이 답하게 한다.

### 4.5 사이드바 창
- 화면 왼쪽에 붙는 항상 위 창. 듀얼 모니터에서는 **교사 화면**에 둔다.
- 고정 모드에서는 윈도우의 AppBar로 등록해 다른 창이 최대화돼도 사이드바를 덮지 않는다.
- 자동 숨김 모드: 왼쪽 끝 몇 픽셀만 남기고 숨었다가, 마우스를 대거나 단축키(예: Ctrl+Shift+Space)를 누르면 나타난다. 모니터 한 대(또는 복제 모드)일 때 권장.
- PPT 전체 화면 슬라이드 쇼 위에서도 보이도록 최상위 단계로 띄운다. 맥은 전체 화면 공간에서도 보이게 별도 설정이 필요하다 → PoC.

## 5. 화면 분할

### 5.1 사용 흐름
1. 사이드바에서 체크 상자 또는 Ctrl/⌘+클릭으로 자료 2~4개 선택 (열려 있지 않은 자료는 자동으로 연다)
2. 배치 선택: **반반 · 7:3 · 3분할 · 큰 화면+2 · 4분할**
3. 고른 순서대로 왼쪽부터 배치한다. 듀얼 모니터에서는 학생 화면에, 모니터 한 대에서는 사이드바를 뺀 영역에 놓는다.
4. 창과 창 경계에 나타나는 **조절 바**를 끌면 양쪽 창 크기가 함께 바뀐다.
5. **분할 해제**를 누르면 원래 위치와 크기로 돌아간다.

### 5.2 구현
- 윈도우: `SetWindowPos`로 위치·크기 지정. 최대화된 창은 먼저 복원, 모니터별 배율(DPI) 보정, 창 그림자 테두리 보정(`DwmGetWindowAttribute`의 실제 테두리 값 사용)
- 맥: 접근성 API로 위치(`kAXPosition`)·크기(`kAXSize`) 설정. 전체 화면 상태인 창은 먼저 전체 화면을 해제
- 웹 자료는 처음부터 각자 창이므로 그대로 배치한다.
- 조절 바: 경계 위치에 띄우는 얇은 항상 위 창. 끄는 동안 양쪽 창 크기를 초당 30번 정도 갱신하고, 무거운 프로그램이 따라오지 못하면 "끄는 동안 안내선만 보여 주고 놓을 때 적용" 방식으로 바꾼다(설정).

### 5.3 주의할 점
- PPT 전체 화면 슬라이드 쇼는 반쪽에 넣을 수 없다 → 분할할 때는 "창 모드 슬라이드 쇼(읽기용 보기)"로 바꿔 배치한다.
- 프로그램마다 최소 크기가 있어 아주 좁게는 줄어들지 않는다. 조절 바와 배치 버튼은 그 이하로 줄이지 않고 최소 폭에서 멈춘다. (맥 검증: 브라우저 최소 폭 500포인트 → 1280 폭 학생 화면에서 7:3을 고르면 61:39로 조정)
- 관리자 권한으로 실행된 프로그램 창은 윈도우 보안 정책상 일반 앱이 옮길 수 없다. 사전 점검에서 알려 준다.

## 6. 듀얼 모니터 (교사 화면 + 학생 화면)

교실에서 흔한 구성은 **노트북·교탁 모니터(교사 화면)**와 **프로젝터·전자칠판·TV(학생 화면)**다. 수업 사이드바는 이 구성을 기본으로 생각한다.

### 6.1 화면 역할 정하기
- **확장 모드**가 기준이다. 처음 연결할 때 "화면 확인"을 누르면 각 화면에 큰 숫자가 뜨고, 학생 화면을 고른다.
- 고른 결과는 모니터 이름(예: EPSON 프로젝터)으로 이 PC에 기억한다. 같은 교실이면 다음부터 자동이다. 처음 보는 모니터면 "외부 모니터 = 학생 화면"으로 추정하고 한 번 확인한다.
- **복제(미러) 모드**면 두 화면이 같아서 사이드바가 학생에게도 보인다. 사전 점검에서 알려 주고, 자동 숨김을 권하거나 확장 모드로 바꾸는 방법(윈도우 Win+P, 맥 디스플레이 설정)을 안내한다.

### 6.2 무엇이 어느 화면에

| 대상 | 기본 화면 | 비고 |
|---|---|---|
| 사이드바 | 교사 화면 | 학생에게 안 보이므로 고정 모드로 써도 된다 |
| 자료 창 | 학생 화면 | 자료마다 바꿀 수 있다 (lesson.json `screen`) |
| 진행 메모, 수업 폴더 | 교사 화면 | |
| 화면 분할 | 학생 화면 | 분할할 화면을 고를 수 있다 |
| 확대, 캡처 핀 | 학생 화면 | "마우스가 있는 화면"으로 바꿀 수 있다 |
| 포인터 강조, 스포트라이트 | 마우스가 있는 화면 | |
| 녹화 | 학생 화면 | 교사 화면이나 두 화면 모두로 바꿀 수 있다 |
| PPT 슬라이드 쇼 | 학생 화면 | 파워포인트 "발표자 보기"를 쓰면 교사 화면에 발표자 보기가 뜬다 → 파워포인트 설정과 맞춘다 (PoC) |

- 사이드바 항목의 **⇄ 버튼**으로 열린 창을 다른 화면으로 옮긴다. 학생 화면으로 옮기면 그 화면에 꽉 차게 놓는다.

### 6.3 학생 화면 관리 (교사 화면에서)
- **학생 화면 미리보기**: 사이드바 위쪽에 학생 화면을 작게 실시간으로 보여 준다(초당 2~5장, 저해상도). 뒤돌아 화면을 보지 않아도 학생에게 무엇이 보이는지 안다.
- **정지**: 지금 장면을 학생 화면에 고정해 두고, 그동안 뒤에서 창을 정리하거나 다음 자료를 준비한다. 다시 누르면 새 장면이 보인다. 미리보기에는 실제 상태가 보인다.
- **가리기**: 학생 화면을 검은 화면과 "잠시 후 계속합니다" 문구로 가린다.

### 6.4 연결이 바뀔 때
- 수업 중 프로젝터 연결이 끊기면 학생 화면에 있던 창을 교사 화면으로 모으고 사이드바에 알린다. 다시 연결되면 원래 화면으로 돌려놓는다 (Electron `screen`의 모니터 추가·제거 이벤트).
- 화면마다 배율이 다르다(노트북 200%, 프로젝터 100% 등). 창 위치·크기를 계산할 때 화면별 배율을 반영한다 (윈도우 모니터별 DPI, 맥 Retina).
- 분할 배치는 "학생 화면 + 비율"로 저장하므로 교실이 바뀌어 해상도가 달라도 같은 모양이 된다.
- 맥은 "디스플레이마다 별도 공간 사용" 설정에 따라 전체 화면 동작이 달라진다 → PoC에서 두 설정 모두 확인.

## 7. 발표 도구

모두 화면 전체를 덮는 투명 오버레이 창(화면마다 하나)에서 처리하므로 한글·PPT·브라우저 어디 위에서나 똑같이 동작한다.

| 도구 | 동작 | 끄기 | 비고 |
|---|---|---|---|
| 확대 | 화면을 멈추고 2배 확대, 마우스로 이동, 휠로 1.5~4배 | Esc 또는 클릭 | 실시간 확대는 2단계 이후 검토 |
| 포인터 강조 | 커서 주변 노란 원, 클릭하면 물결 | 같은 버튼 | 클릭은 그대로 아래 프로그램에 전달 |
| 캡처 핀 | 영역을 끌어 선택 → 항상 위 작은 창으로 고정, 이동·닫기 | 핀의 ✕ | `_캡처/` 폴더에 자동 저장 |
| 스포트라이트 | 화면을 어둡게, 커서 주변만 밝게, 휠로 크기 | Esc | |

포인터 강조와 스포트라이트는 녹화 영상에도 찍혀서 다시 볼 때 어디를 가리켰는지 보인다.

## 8. 화면 녹화

- 녹화할 화면 선택 (기본: 학생 화면), 마이크 + 컴퓨터 소리 (맥은 OS 버전에 따라 제한 → PoC 확인)
- 이 PC의 임시 폴더에 2초마다 기록 → 앱이 꺼져도 그때까지는 남고, 다음 실행 때 복구. 끝나면 수업 폴더 `_녹화/`로 옮긴다 (9.3)
- **챕터 자동 기록**: 앞 창이 바뀔 때마다 `00:00 오프닝 영상`, `03:12 연수 안내` 같은 목차를 저장. 다음 연수 준비 때 원하는 부분으로 바로 이동
- 용량: 1080p 약 2.5~4GB/시간, 720p 약 1~1.5GB/시간. 시작 전에 남은 공간 확인
- 사양이 낮은 PC는 "가벼운 녹화(720p 15fps)"

- PPT·한글 미리보기 같은 캐시는 수업 폴더에 넣지 않고 각 PC의 앱 데이터 폴더에 둔다 (동기화 낭비 방지).

- `screen`은 "student" / "teacher"로 적는다. 모니터 한 대일 때는 무시한다.
- `layouts`는 자주 쓰는 화면 분할을 저장해 두었다가 한 번에 다시 배치하는 용도다.

### 9.3 클라우드 폴더로 윈도우·맥을 오가며 편집 (기본 방식)

**원칙: 앱은 도구, 수업은 폴더.** 수업에 필요한 모든 것(lesson.json, 자료, 메모, 캡처, 녹화와 챕터, 수업안내.html)은 수업 폴더 안에만 있다. 앱 쪽에는 "최근 연 폴더"와 "이 PC 설정"만 남는다. 그래서 폴더가 있는 곳이면 어느 PC의 수업 사이드바로든 열어 이어서 편집할 수 있다. 문서 프로그램이 파일을 열듯, 수업 사이드바는 수업 폴더를 연다.

**사용 흐름**
1. 윈도우 PC와 맥에 구글 드라이브 데스크톱 앱을 설치하고 같은 계정으로 로그인
2. 수업 사이드바 설정에서 **수업 보관함** 위치를 `내 드라이브/수업 사이드바/`로 한 번 지정
3. 윈도우에서 준비하고 저장 → 폴더가 그대로 드라이브에 올라감
4. 맥의 수업 사이드바 보관함에 같은 수업이 보이고, 열어서 이어서 편집

- 수업 사이드바는 **드라이브 API를 쓰지 않는다.** 동기화는 드라이브 데스크톱 앱이 맡고, 사이드바는 평범한 폴더를 읽고 쓸 뿐이다. 구글 로그인, OAuth 심사, 토큰 관리가 모두 필요 없다.
- 같은 이유로 OneDrive, Dropbox, 학교 NAS, USB 메모리도 똑같이 쓸 수 있다.

**폴더 안에 두는 것과 이 PC에만 두는 것**

| 수업 폴더 안 (PC를 옮겨도 따라감) | 이 PC에만 (따라가지 않음) |
|---|---|
| lesson.json: 흐름, 자료, 메모, 시작 위치, 화면, 분할 배치 | 최근 연 폴더 목록, 수업 보관함 위치 |
| 자료 파일, 메모, 링크, 캡처, 수업안내.html | 자료 종류별로 쓸 프로그램의 실제 위치, 쓸 브라우저 |
| 녹화 영상과 챕터 | 어느 모니터가 학생 화면인지, 사이드바 폭, 단축키 |
| `.sidebar/locks/`, `.sidebar/backup/`, `.sidebar/휴지통/` | 미리보기 캐시, 권한 상태 |

**두 PC가 부딪히지 않게**
- **잠금 파일**: 수업을 열면 `.sidebar/locks/<PC 이름>.json`에 시각을 쓰고 30초마다 갱신한다. PC마다 자기 파일만 쓴다 (한 파일을 여러 PC가 번갈아 쓰면 서로의 표시를 지우고 드라이브가 충돌 사본을 만들기 때문, 맥 체험판에서 확인). 다른 PC에서 같은 수업을 열 때 잠금이 살아 있으면 "윈도우 PC(교실)에서 편집 중 · 1분 전 활동 → 읽기 전용으로 열기 / 그래도 편집"을 묻는다. 5분 넘게 갱신이 없는 잠금은 끝난 것으로 본다. (동기화에는 몇 초~몇 분이 걸리므로 잠금은 "경고"이지 완전한 차단이 아니다.)
- **바깥 변경 감지**: 폴더 감시와 함께 5초마다 lesson.json 수정 시각을 확인한다. 다른 PC에서 고친 내용이 도착하면 "새 내용으로 다시 불러오기"를 띄운다. 이쪽에서 편집 중인 내용이 없으면 자동으로 불러온다.
- **충돌**: 두 PC에서 따로 고쳐 드라이브가 `lesson (1).json` 같은 충돌 사본을 만들면, 사이드바가 이를 찾아 두 버전을 나란히 보여 주고 고르게 한다. 고르지 않은 쪽은 `.sidebar/backup/`에 남긴다.
- **저장**: 임시 파일에 쓰고 바꿔치기(원자적 저장) + 최근 10개 백업. 동기화 앱이 반쯤 쓰인 파일을 올리는 일을 막는다.
  - 준비 화면에는 저장 버튼이 없다. 바꿀 때마다 바로 저장하고, 글자 칸은 치다 멈출 때(1.2초)·칸을 벗어날 때·다른 창으로 갈 때·창을 닫을 때(동기 저장) 저장한다.
  - 자주 저장하므로 백업은 1분에 하나만 만든다(10개가 금방 밀려나지 않게). 다른 PC에서 바뀐 파일을 덮게 될 때는 시간과 상관없이 먼저 백업한다.

**동기화가 덜 됐을 때**
- 아직 내려오지 않은 파일은 목록에 "동기화 기다리는 중"으로 표시하고, 도착하면 자동으로 정상 표시로 바꾼다.
- 드라이브 데스크톱의 **스트리밍 모드**는 파일을 열 때 내려받아서 수업 중 느릴 수 있다. 사전 점검의 **"수업 전에 모두 내려받기"**가 모든 파일을 한 번씩 읽어 이 PC에 받아 두고, 드라이브에서 수업 폴더를 "오프라인 사용 가능"으로 지정하라고 안내한다.
- **녹화는 이 PC의 임시 폴더에 먼저 기록**하고, 녹화가 끝나면 수업 폴더의 `_녹화/`로 옮긴다. 녹화 중 계속 커지는 파일을 동기화 앱이 반복해서 올려 수업 PC가 느려지는 일을 막기 위해서다.

**PC를 오가도 깨지지 않게**
- 파일 위치는 모두 수업 폴더 기준 상대 경로
- 새로 만드는 파일 이름은 NFC로 저장하고, 읽을 때는 NFC와 NFD를 같은 이름으로 취급한다 (맥에서 만든 한글 파일 이름이 윈도우에서 다르게 보이는 문제 방지)
- 윈도우에서 쓸 수 없는 문자와 너무 긴 경로는 만들 때부터 막는다
- lesson.json의 `schema` 번호로 버전을 구분한다. 한쪽 PC의 사이드바가 더 오래된 버전이면 새 형식의 수업을 읽기 전용으로 열고 업데이트를 안내한다.

**구글 문서를 수업 폴더에 직접 넣으면**
- 드라이브 데스크톱 폴더 안의 구글 문서·시트·슬라이드는 `.gdoc`, `.gsheet`, `.gslides` 바로가기 파일로 보인다. 사이드바는 이 파일에서 주소를 읽어 브라우저 새 창으로 연다.

### 9.4 수업 꾸러미(.zip) — 클라우드를 못 쓰는 PC, 동료에게 넘길 때

드라이브 데스크톱 앱을 설치할 수 없는 학교 PC, USB만 쓸 수 있는 연수장, 동료 선생님께 수업을 통째로 넘길 때 쓴다. 드라이브 웹에서 수업 폴더를 내려받으면 zip이 되는데, 이 zip도 그대로 가져올 수 있다.

**내보내기**
- 준비 화면의 "꾸러미로 내보내기" → `2026-11-28_AI활용수업설계연수_1차.zip` 하나로 저장
- 담기는 것: `lesson.json`, 모든 자료 파일, 메모(.md), 링크(.url), `수업안내.html`, `_캡처/`, `.sidebar/manifest.json`
- zip 안 맨 위에 수업 폴더 이름을 둔다 (손으로 풀어도 폴더 하나, 드라이브 웹 zip과 같은 모양). 잠금·백업·휴지통(`.sidebar/`의 나머지), 문서 프로그램 임시 파일(`~$…`), 실행 파일은 넣지 않는다
- (첫 버전 2026-11-21: 링크는 lesson.json 안에만 있고 .url·수업안내.html·_캡처는 아직 없다)
- 녹화 영상은 용량이 커서 **선택 사항**(체크 상자, 예상 용량 표시)
- `.sidebar/manifest.json`: 꾸러미 형식 버전, 앱 버전, 만든 날짜, 파일 목록과 SHA-256(가져올 때 손상 확인용). 자료 중에 `manifest.json`이라는 파일이 있어도 겹치지 않게 `.sidebar` 안에 둔다
- 보내기 전에 "정리하기"(순번 맞추기)를 자동 실행
- 받는 사람 계정에 열람 권한이 있어야 열리는 구글 문서·캔바 링크를 목록으로 미리 알려 준다

**가져오기**
- "꾸러미 가져오기" 또는 사이드바 창에 zip을 끌어다 놓기
- 검사: manifest 확인 → 파일 해시 확인 → 위험한 경로 차단(`../`, 절대 경로) → 압축 해제 용량 제한 → 실행 파일 차단
- 같은 수업이 이미 있으면(같은 수업 번호 또는 같은 폴더 이름) **사본으로 가져오기 / 덮어쓰기(기존 수업 백업) / 취소** 중 선택
  - 사본: `_2` 폴더, 새 수업 번호, 이름에 "(사본)"
  - 덮어쓰기: 지금 폴더를 보관함의 `.sidebar/덮어쓰기 전/<폴더>_<시각>`으로 옮긴 뒤 그 자리에 푼다. 사이드바에서 진행 중인 수업은 덮어쓰지 않는다
- 숨은 임시 폴더(`.가져오는 중-…`)에 다 푼 뒤 확인이 끝나면 바꿔치기한다. 중간에 실패해도 보관함이 망가지지 않는다
- 제한: 파일 5,000개, 풀었을 때 20GB, 파일 하나 8GB, 저장 공간 확인. 위험한 경로가 하나라도 있으면 꾸러미 전체를 거절한다
- 윈도우 탐색기로 묶은 zip(한글 이름이 CP949, UTF-8 표시 없음, 역슬래시)도 읽는다
- 가져온 즉시 편집 가능. 사전 점검을 자동으로 한 번 실행해 이 PC에 필요한 프로그램(한글·PPT 등)이 있는지 확인
- 맥에서 만든 한글 파일 이름(NFD)은 꾸러미에 넣을 때 NFC로 바꾸고 zip의 UTF-8 표시를 켜서, 윈도우에서 "ㅎㅏㄴㄱㅡㄹ"처럼 깨지지 않게 한다

### 9.5 드라이브 API 직접 연동은 하지 않는다

9.3 방식으로 요구사항(드라이브에 폴더 단위로 정리, 녹화 포함, 여러 PC에서 편집)이 모두 충족되므로 드라이브 API는 쓰지 않는다. 드라이브 데스크톱 앱을 설치할 수 없는 PC가 많아 꾸러미로도 불편할 때만 다시 검토한다. 그때의 조건: `drive.file` 권한, OAuth 앱 "프로덕션" 상태(테스트 상태는 7일마다 재로그인), 시스템 브라우저 로그인, 이어 올리기.

## 10. 기술 선택

- **사이드바 앱**: Electron(최신 안정 버전) + TypeScript + React + Vite, 패키징 electron-builder
  - 웹 화면을 앱 안에 띄울 필요가 없어 Tauri도 후보지만, 녹화·화면 캡처·화면별 오버레이·모니터 감지를 빠르고 안정적으로 만들 수 있는 Electron을 쓴다. 사이드바 자체 메모리는 약 150~250MB.
- **창 관리 도우미**: 운영체제별 작은 도우미를 별도 프로세스로 실행 (멈추면 자동 재시작). 프로그램 안에 함께 들어 있어 따로 설치할 것은 없다.
  - 윈도우: koffi(FFI)로 user32·dwmapi 호출
  - 맥: Swift 도우미 (접근성 API, CoreGraphics 창 목록)
- **브라우저**: 확장 프로그램 없이 명령줄 옵션(`--new-window`, `--app`)으로 새 창을 열고 창 관리 도우미로 추적
- **모니터**: Electron `screen` (모니터 목록·배율·추가/제거 이벤트), 학생 화면 미리보기는 `desktopCapturer` 저해상도
- **녹화**: `desktopCapturer` + `MediaRecorder` (MP4 가능하면 MP4, 아니면 WebM), 필요 시 ffmpeg로 마무리
- **클라우드**: 직접 연동하지 않는다. 구글 드라이브 데스크톱·OneDrive·Dropbox가 동기화하는 평범한 폴더를 읽고 쓴다. 폴더 감시(chokidar)와 수정 시각 확인을 함께 쓴다 (클라우드 가상 드라이브에서는 폴더 감시 알림이 빠질 수 있어서)
- **꾸러미**: zip 만들기·풀기는 yazl/yauzl (UTF-8 표시, 경로 검사 직접 구현)
- **데이터**: 수업마다 `lesson.json`, 전체 검색 색인은 나중에

```

│ LessonStore   수업 폴더·lesson.json, 원자적 저장, 백업                 │
```

### 10.1 윈도우·맥 함께 지원

**만드는 양의 대부분은 한 번 만들면 두 OS에서 같이 동작한다.** 준비 화면, 수업 폴더와 lesson.json, 보관함·잠금, 사이드바 화면, 오버레이 도구, 녹화, 꾸러미, 모니터 감지는 공통 코드다. OS마다 따로 만드는 것은 **창 관리 도우미, 사이드바 고정 방식, 권한 안내, 설치 파일·서명** 네 가지다.

| 기능 | 윈도우 | 맥 |
|---|---|---|
| 창 찾기·앞으로·닫기 | user32 API (koffi), 따로 허용할 권한 없음 | 접근성 API (Swift 도우미), "손쉬운 사용" 권한 한 번 허용 |
| 화면 분할·다른 화면으로 옮기기 | `SetWindowPos`, 모니터별 배율(DPI)·창 그림자 보정 | 접근성 API로 위치·크기, 전체 화면 창은 먼저 해제. 외부 모니터의 메뉴 막대를 macOS가 사용 영역에서 빼 주지 않아 메뉴 막대 높이를 직접 읽어 뺀다 (검증에서 확인) |
| 브라우저 새 창 | `chrome.exe --new-window` (엣지 `msedge.exe`, 웨일 `whale.exe`) | `open -na "Google Chrome" --args --new-window` |
| 사이드바 고정 | AppBar로 등록 → 다른 창이 최대화돼도 사이드바를 덮지 않음 | AppBar가 없음 → 항상 위 패널, 분할 영역에서 사이드바 폭을 빼고 배치 |
| PPT 슬라이드 쇼 위에 사이드바·도구 | 최상위 창으로 표시 | 슬라이드 쇼가 별도 전체 화면 공간 → 전체 화면 위에도 보이는 패널로 설정 (PoC 확인) |
| PPT 시작 슬라이드 지정 | COM 자동화 | AppleScript |
| 한글 | `Hwp.exe`, 창 제목 "파일명 - 한글" | 한컴오피스 HWP for Mac, 창 제목 형식은 PoC에서 확인 |
| 녹화 소리 | 마이크 + 컴퓨터 소리 | 마이크 + 컴퓨터 소리 (macOS 13 이상, 이 맥은 해당) → PoC 확인 |
| 화면 캡처·녹화·미리보기 권한 | 따로 없음 | "화면 기록" 권한 한 번 허용 |
| 단축키 | Ctrl 기준 | ⌘ 기준 (같은 단축키를 자동으로 바꿔 표시) |
| 설치 파일 | 설치형 .exe + 설치 없이 실행하는 portable .exe (학교 PC용) | .dmg (Apple Silicon·Intel 겸용) |
| 서명 | 미서명이면 처음 실행 때 SmartScreen 경고 ("추가 정보 → 실행"으로 통과). 동료에게 나눌 때 인증서 검토 | 미서명이면 실행 경고 + 새 버전마다 화면 기록·손쉬운 사용 권한이 풀림 → 혼자 쓸 때는 키체인의 자체 서명 인증서로 서명해 권한 유지, 나눌 때는 Apple 개발자 등록(연 99달러)과 공증 |

**개발과 테스트 방식: 맥의 Claude와 윈도우의 Claude가 GitHub로 협업**

윈도우 PC에도 Claude Code를 설치하고 같은 GitHub **비공개** 저장소에 연결한다. 윈도우 쪽 Claude가 프로그램을 직접 실행하고 오류 기록을 읽어 그 자리에서 고치므로, 결과 파일을 사람이 주고받는 단계가 없어지고 윈도우에서만 생기는 문제를 훨씬 빨리 잡는다.

| | 맥의 Claude | 윈도우의 Claude |
|---|---|---|
| 맡는 코드 | 공통 코드(준비 화면, 사이드바 화면, 수업 폴더, 꾸러미, 녹화, 오버레이, 모니터 관리), 맥 창 관리 도우미(Swift), 맥 설치 파일 | 윈도우 창 관리 도우미(user32), 윈도우 설치 파일과 설치 없이 실행 버전, 윈도우 전용 수정 |
| 직접 테스트 | 맥 + 외부 모니터, 한컴오피스 HWP for Mac, PowerPoint for Mac, 크롬 | 윈도우 + 프로젝터/외부 모니터, 한글, PowerPoint, 크롬·엣지·웨일 |
| 공통 코드에서 상대 OS 문제를 찾으면 | 이슈로 남기고 담당 쪽에 넘김 | 작은 수정은 별도 브랜치 + PR, 큰 수정은 이슈로 남김 |

작업 규칙
1. 저장소는 하나, 비공개. `main`은 언제나 실행되는 상태로 둔다.
2. 각자 브랜치에서 작업한다 (`mac/…`, `win/…`). 끝나면 PR → 자동 검사 통과 → 합치기.
3. 작업 시작 전에 `git pull`, 작은 단위로 자주 커밋한다.
4. **자동 검사(GitHub Actions)**: PR마다 윈도우·맥 두 환경에서 빌드와 테스트를 돌려, 한쪽 OS에서만 깨지는 변경이 `main`에 들어가지 않게 한다.
5. 저장소에 `CLAUDE.md`(공통 규칙: 한국어로 소통, 폴더 구조, 실행·테스트 명령, 역할 분담)와 `docs/PLAN.md`를 두어 두 Claude가 같은 기준으로 일한다.
6. 진행 상황과 남은 일은 `HANDOFF.md`에 적어 다른 쪽 Claude가 바로 이어받는다.
7. 0단계 기술 검증 결과는 `docs/poc/windows.md`, `docs/poc/mac.md`에 항목별 통과/실패와 원인으로 남긴다.
8. 학생 정보가 담긴 실제 수업 자료와 녹화 파일은 저장소에 올리지 않는다 (`.gitignore`, 예시 자료만 사용).

윈도우 PC에 준비할 것: Git, Node.js LTS, GitHub 로그인(GitHub CLI), Claude Code, 한글·PowerPoint·Excel, 외부 모니터 또는 프로젝터. 창 제어에 쓰는 koffi는 미리 빌드된 파일을 쓰므로 Visual Studio 빌드 도구는 필요 없을 것으로 본다 (PoC에서 확인).

**사람이 직접 봐야 하는 것**: 사이드바가 PPT 슬라이드 쇼 위에 보이는지, 자료가 학생 화면에 제대로 뜨는지, 정지·가리기가 자연스러운지처럼 눈으로 확인할 부분은 선생님이 보고 알려 주신다. 각 Claude는 확인할 항목을 체크리스트로 드린다.

- 맥의 가상 윈도우(ARM)는 창 제어·오피스 동작이 실제 학교 PC와 달라 쓰지 않는다.
- 0단계 PoC는 두 OS 모두에서 통과해야 1단계로 간다.

**개발 환경 확인 (2026-11-21, 이 맥)**: Apple Silicon, Node.js 24, npm 11, git, GitHub CLI(로그인됨), Xcode·Swift 6.4 → Electron 앱과 맥용 Swift 도우미를 바로 만들 수 있다.

## 11. 안정성 설계 (실패 상황별 대응)

| 상황 | 대응 |
|---|---|
| 한 프로그램이 멈춤 | 사이드바와 다른 프로그램은 영향 없음. 사이드바에 "응답 없음" 표시 |
| 자료가 10초 안에 안 열림 | "다시 열기 / 다른 프로그램으로 열기" 버튼 표시 |
| 창을 못 찾음 | 다시 찾기 → 실패 시 열린 창 목록에서 직접 연결 |
| 브라우저를 처음 켤 때 이전 창들이 함께 복원됨 | 주소가 맞는 창을 연결, "모두 미리 열기" 때 브라우저부터 띄움 |
| 수업 중 프로젝터 연결이 끊김 | 학생 화면 창을 교사 화면으로 모으고 알림, 다시 연결되면 원래 화면으로 |
| 복제(미러) 모드로 연결됨 | 사전 점검에서 알림, 자동 숨김 권장, 확장 모드 전환 방법 안내 |
| 화면마다 배율이 다름 | 위치·크기 계산에 화면별 배율 반영 |
| 수업 중 인터넷 끊김 | 로컬 파일은 정상, 웹 자료는 준비 때 저장한 스냅샷(PDF) 열기 |
| 사이드바가 강제로 꺼짐 | 다시 켜면 열린 창들을 다시 찾아 연결, lesson.json 원자적 저장 + 최근 10개 백업, 녹화 복구 |
| 원본 파일이 옮겨지거나 지워짐 | 수업 폴더에 복사본이 있어 영향 없음 |
| 학교 PC가 재부팅 때 초기화됨 | 수업 꾸러미(.zip)를 USB·드라이브에 보관 → 가져오기, 설치 없이 실행되는 버전 |
| 꾸러미 파일이 손상됨 | manifest 해시로 손상 파일을 찾아 알려 주고, 멀쩡한 파일은 그대로 가져옴 |
| 윈도우와 맥에서 같은 수업을 동시에 엶 | 잠금 파일로 경고 → 읽기 전용 또는 그래도 편집, 충돌 사본이 생기면 나란히 비교해 고르기 |
| 다른 PC의 변경이 아직 덜 내려옴 | 빠진 파일은 "동기화 기다리는 중" 표시, 도착하면 자동 반영, lesson.json이 바뀌면 다시 불러오기 |
| 드라이브 스트리밍 모드라 수업 중 파일이 늦게 열림 | 사전 점검 "수업 전에 모두 내려받기" + 폴더 오프라인 사용 안내 |
| 녹화 중 동기화 앱이 큰 파일을 계속 올려 PC가 느려짐 | 녹화는 이 PC 임시 폴더에 기록, 끝난 뒤 수업 폴더로 옮김 |
| 두 PC의 사이드바 버전이 다름 | lesson.json `schema` 번호 확인 → 오래된 쪽은 읽기 전용 + 업데이트 안내 |
| 프로젝터 해상도가 낮음 (1024×768, 1366×768) | 분할 배치는 비율로 계산, 사이드바는 교사 화면에 있어 영향 없음 |
| 녹화 중 디스크 부족 | 시작 전 예상 용량 확인, 2GB 아래로 내려가면 경고 후 자동 정지 |
| 창 관리 도우미가 꺼짐 | 자동 재시작, 그동안 목록·열기는 계속 동작 |
| 프로그램에 확인·로그인 창이 떠 있어 닫기·전환이 안 됨 | "답을 기다리는 창이 있습니다" 표시 + 그 창을 앞으로 |
| 브라우저가 수업 폴더 파일을 읽을 권한이 없음 (맥 폴더 보호, 학교 관리 정책) | 파일을 내부 주소(127.0.0.1)로 제공해 권한이 필요 없게 함 |

테스트: 실제 학교 PC 사양(윈도우 10/11, 8GB RAM, 1366×768 + 프로젝터)에서 매 단계 확인, 매 단계 끝에 실제 연수에서 한 번 써 보기.

## 12. 보안·개인정보

- 원래 프로그램으로 여는 파일은 수업 폴더 안 파일만 허용, 웹은 http/https만
- 브라우저에 넘기는 주소와 파일 경로는 명령줄 인자로 안전하게 전달한다 (셸 문자열로 이어 붙이지 않음)
- 클라우드 계정 정보는 다루지 않는다 (로그인과 동기화는 각 클라우드 앱이 담당)
- 내부 주소(127.0.0.1) 파일 제공: 이 PC 밖에서는 접속할 수 없게 127.0.0.1에만 열고, 실행할 때마다 바뀌는 무작위 토큰이 맞는 요청만 받으며, 수업 폴더 밖 경로(`..` 등)는 거절한다
- 브라우저 창 제목에는 사용자 프로필 이름이 붙는다. 창 제목은 화면 표시와 짝짓기에만 쓰고, lesson.json·기록 파일·녹화 챕터에는 자료 이름만 남긴다
- 로그인 창·암호 입력 창은 사이드바가 절대 건드리지 않는다 (앞으로 가져오기만)
- 수업 폴더 안 lesson.json은 다른 PC나 다른 사람이 고친 것일 수 있으므로, 읽을 때 형식을 검증하고 파일 경로가 수업 폴더 밖을 가리키면 무시한다
- 꾸러미 가져오기: 수업 폴더 밖으로 풀리는 경로 차단(zip slip), 압축 해제 총용량·파일 수 제한(zip 폭탄), 실행 파일(.exe, .bat, .app, .command 등)은 가져오지 않고 알림
- **녹화·캡처·미리보기 개인정보**: 학생 얼굴·목소리·이름이 담길 수 있다. 녹화 중 REC 표시, 시작 시 안내 문구, 저장은 본인 드라이브, 공유 전 확인. 학생 화면 미리보기는 저장하지 않는다. 학교 개인정보 지침을 따른다.
- 유튜브 영상은 내려받지 않고 링크·제목·썸네일만 저장한다(유튜브 약관).

## 13. 개발 로드맵

각 단계가 끝나면 실제 연수에서 한 번 써 보고 다음 단계로 간다.

**0단계 — 기술 검증 PoC (2~3주, 윈도우·맥 각각)**
1. 한글·PPT·엑셀 창 찾기 → 앞으로 → 배치 → 닫기
2. 브라우저 새 창 열기와 추적 (크롬·엣지·웨일, 브라우저가 꺼져 있을 때 포함)
3. 듀얼 모니터: 창을 학생 화면으로 옮겨 꽉 채우기, 배율이 다른 화면, 연결 끊김·재연결, PPT 슬라이드 쇼가 뜨는 화면
4. PPT 전체 화면 슬라이드 쇼 위에 사이드바·오버레이 표시
5. 60분 연속 녹화 (CPU 사용률, 용량, 소리)
6. 구글 드라이브 데스크톱 폴더에서 윈도우 ↔ 맥 편집 왕복 (잠금 파일, 충돌 사본, 한글 파일 이름 NFC/NFD, 스트리밍 모드 속도)
7. 학교 PC에서 실행 (설치 권한, 보안 프로그램, 사이트 차단)

**1단계 — 수업에 쓸 수 있는 최소 버전**
- 준비 화면(구간·자료·순서·여는 프로그램·화면), 폴더 자동 정리, lesson.json
- **수업 보관함**: 보관함 위치 지정, 수업 폴더 열기·새로 만들기·최근 목록, 잠금 파일, 바깥 변경 감지
- **수업 꾸러미(.zip) 내보내기·가져오기**
- 사이드바: 열기·앞으로·현재 화면 강조·닫기·자동 숨김, 모두 미리 열기
- 듀얼 모니터 기본: 화면 역할 정하기, 자료를 학생 화면에 열기, ⇄ 다른 화면으로 옮기기, 연결 끊김 처리

**2단계 — 수업 도구**
- 화면 분할(배치 5종, 조절 바, 복원, 배치 저장)
- 확대·포인터 강조·캡처 핀·스포트라이트 (화면마다)
- 학생 화면 미리보기·정지·가리기
- 녹화 + 챕터

**3단계 — 정리와 재사용**
- 사전 점검(수업 전에 모두 내려받기, 모니터 확인 포함), 충돌 사본 비교 화면, 수업 복제(2차 연수 만들기), 수업안내.html, 지난 수업 검색
  - 사전 점검 첫 버전 (2026-11-22, `app/src/core/precheck.js`): 준비 화면 "사전 점검" 단추, 꾸러미를 가져오면 자동 실행
    - 자료마다: 파일을 끝까지 한 번 읽음(클라우드 폴더면 이때 내려받음) → 여는 프로그램이 이 PC에 있는지(없으면 대안: 한글 뷰어·PDF) → 링크
    - 링크는 로그인 없이 열어 보고, 마지막에 도착한 주소가 로그인 화면이면 "로그인해야 열림(링크 공유 꺼짐)". 유튜브는 oEmbed로 공개·비공개. 이 PC의 인터넷 설정(학교 프록시)을 따르도록 Electron `net.fetch`를 쓴다
    - 이 PC: 인터넷, 브라우저, 모니터(1개면 자동 숨김 권장, 복제 모드 안내), 창 제어 권한, 저장 공간, 다른 PC가 열고 있는지, 클라우드 폴더면 "오프라인 사용" 안내
    - 결과는 문제 → 주의 → 정상 순서. 아직 없는 것: 관리자 권한 창 알림, 화면 기록 권한(녹화가 생기면), 수업 시작 직전 자동 점검

**4단계 — 확장**
- 교사 화면 발표자 모드(진행 메모·구간 타이머·다음 자료 미리보기), 판서 펜, 휴대폰 리모컨, 서명·자동 업데이트

## 15. 보완 제안

**꼭 넣기를 권하는 것**
- **수업 시작 · 모두 미리 열기**: 사이드바 방식의 유일한 약점(처음 켤 때 느림)을 없앤다
- **사전 점검 버튼**: 링크·파일·필요 프로그램·브라우저·모니터·권한을 한 번에 확인
- **자료별 시작 위치**: 유튜브 몇 분부터, PDF 몇 쪽부터, PPT 몇 번 슬라이드부터
- **분할 배치 저장**: "설문 결과 + 활동지" 같은 배치를 수업 흐름에 항목으로 넣어 클릭 한 번에 다시 배치
- **학생 화면 정지·가리기**: 다음 자료를 준비하는 어수선한 모습을 학생에게 보이지 않기
- **단축키·클리커**: 다음/이전 자료, 도구 켜고 끄기 (PPT 클리커와 겹치지 않게)
- **수업 복제**: "이 연수로 2차 만들기"
- **수업안내.html + 녹화 챕터**: 다음 연수 준비 때 앱 없이도 흐름·자료·녹화 위치를 바로 찾음
- **웹 자료 스냅샷**: 준비할 때 웹 페이지를 PDF로 저장해 인터넷이 끊겨도 대비

**있으면 좋은 것**
- 교사 화면 발표자 모드: 진행 메모, 구간 타이머, 다음 자료 미리보기
- 학생 공유 QR: 지금 보이는 자료의 링크를 큰 QR로 띄우기
- 판서 펜, 태그·검색, 수업 후 회고 메모, 휴대폰 리모컨
