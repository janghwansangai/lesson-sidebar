## 알게 된 것 (설계에 반영)

1. **브라우저는 LaunchServices(`open -na <앱> --args --new-window <주소>`)로 연다.** 실행 파일을 직접 부르면 부른 프로그램의 제한을 물려받는다. 이번에는 시험 환경의 제한 때문에 엣지가 자기 설정 폴더를 만들지 못하고 바로 꺼졌다. `open`으로 열면 독립된 프로그램으로 실행되어 문제가 없다.
2. **로컬 파일을 `file://`로 브라우저에 넘기면 안 된다.** 엣지가 바탕화면 폴더의 시험 파일을 열려다 macOS의 "데스크탑 폴더의 파일에 접근하려고 합니다" 권한 창을 띄웠고, 답하기 전까지 빈 창이 됐다. 수업 중에 이런 창이 뜨면 곤란하다. 사이드바가 `127.0.0.1` 주소(무작위 토큰 포함, 수업 폴더만)로 파일을 제공하니 권한 창 없이 바로 열렸다. 학교 관리 브라우저가 `file://`을 막는 경우도 피할 수 있다.
3. **외부 모니터에도 메뉴 막대(30포인트)가 있는데 macOS가 사용 영역에서 빼 주지 않는다.** 그래서 창이 30포인트 아래로 밀렸다. 화면마다 떠 있는 메뉴 막대 창의 위치를 직접 읽어 사용 영역에서 빼도록 도우미를 고쳤다 (내장 33, 외부 30). "디스플레이마다 별도 공간 사용"이 꺼져 있어도 메뉴 막대가 보이는 상태였다.
4. **프로그램마다 최소 폭이 있다.** 크롬·엣지·웨일은 500포인트보다 좁아지지 않는다. 1280 폭 학생 화면에서 7:3을 고르면 오른쪽이 384가 되어 창이 겹친다. 조절 바와 배치 버튼은 최소 폭에서 멈추도록 비율을 조정한다 (`fitRatio`).
5. **프로그램에 확인·로그인 창(모달)이 떠 있으면 창 닫기 요청이 무시된다.** 엣지에 학교 Microsoft 계정 로그인 창이 떠 있어 다른 창이 닫히지 않았다. 사이드바는 "이 프로그램에 답을 기다리는 창이 있습니다"를 표시하고 그 창을 앞으로 가져와야 한다. 저장 여부를 묻는 창도 같다.
6. **브라우저 창 제목에 사용자 프로필 이름이 붙는다** (예: "… - Chrome - (프로필 이름)"). 창 제목을 공유 파일이나 기록에 남기지 않는다. 시험 결과 파일(`poc/out/`)은 저장소에 올리지 않는다.
7. 오피스 창 제목은 확장자 없는 파일 이름이다 ("샘플_발표자료"). 한글 파일 이름도 NFC/NFD 차이 없이 짝이 맞았다.

### 체험판에서 새로 알게 된 것
8. **최소화된 창은 접근성 정보에서 종류가 "대화상자(AXDialog)"로 바뀐다.** 그래서 처음에는 최소화된 PPT·메모 창이 목록에서 사라져 "닫힘"으로 잘못 표시됐다. 최소화된 창은 대화상자여도 목록에 넣도록 도우미를 고쳤다.
9. 맥이 한국어일 때 프로그램 이름이 한국어로 나온다 (텍스트 편집기, 한컴오피스 한글). 창 찾기는 프로그램 이름 또는 번들 ID(com.apple.TextEdit 등)로 하므로 문제없다.
10. 앞으로 가져오기가 기술 검증(0.16초)보다 느린 0.7초인 것은 화면 요청 → 도우미 실행 → 맨 앞 확인을 거치기 때문이다. 1단계에서 도우미를 계속 켜 두고 명령을 주고받는 방식으로 줄인다.

## 설치판 (2026-11-21, `app/` electron-builder 26.18.1)
`npm run dist:mac` → `.dmg` 하나(약 119MB). 앱 안에 창 관리 도우미 `winctl`, 공통 로직 `poc/lib`, 예시 수업이 들어간다. 개발자 등록 없이 임시(ad-hoc) 서명.

17. **앱 안쪽 실행 파일 이름(productName)이 한글이면 Electron 45가 준비(ready) 전에 멈춘다** (SIGTRAP, 기록 없음). 아주 작은 시험 앱도 똑같이 멈췄고, 앱 폴더 이름만 영어로 바꿔도 멈췄으며, 실행 파일 이름을 영어(`LessonSidebar`)로 하자 끝까지 켜졌다. 그래서 안쪽 이름은 영어로 두고, 보이는 이름은 `CFBundleDisplayName=LessonSidebar` + `LSHasLocalizedDisplayName` + `ko.lproj/InfoPlist.strings`("수업 사이드바")로 한다. Finder는 폴더 이름이 기본 표시 이름과 같을 때만 한글 이름을 보여 준다 (`CFBundleDisplayName`을 한글로 두면 영어 폴더 이름이 그대로 보였다). 설정 폴더 이름은 `package.json`의 `productName`을 따라 `~/Library/Application Support/수업 사이드바`이고, 이 이름은 한글이어도 괜찮다.
18. `src/core/session.js`가 공통 로직을 `../../../poc/lib/match.js`로 불러오므로, 앱 안에도 같은 상대 위치(`Resources/poc/lib`)에 넣고 ESM으로 읽히게 `poc/package.json`도 함께 넣는다. 빠지면 켜자마자 멈춘다.
19. 설치판은 앱 자신이 손쉬운 사용 권한을 받는다. 개발용은 실행한 프로그램(Claude·터미널)이 권한을 받는다. 권한이 없으면 `trusted --prompt`로 macOS 요청 창을 띄우고, 2초마다 확인해 켜지면 바로 창 연결을 시작한다. 임시 서명이라 새로 빌드하면 서명 값이 바뀌어 권한을 다시 켜야 할 수 있다. 계속 유지하려면 키체인의 자체 서명 인증서로 서명해야 한다 (`docs/PLAN.md` 10.1). 인증서는 선생님이 직접 만들어야 한다.
**선생님 설치 확인 (2026-11-21)**: `.dmg`로 응용 프로그램 폴더에 설치 → 손쉬운 사용 권한 켜기 → "잘 된다". 쓰던 설정(보관함·마지막 수업)은 개발용 설정에서 옮겨 둠.

20. 자동 검사에 "맥 설치판 만들어 켜 보기"를 넣었다 (`npm run dist:mac:dir` → `npm run smoke:mac`). 17·18 같은 문제를 PR 단계에서 잡는다.

## 윈도우 Claude가 넣은 사이드바 기능 (2026-11-22, PR #17 → `mac/sidebar-options`)
22. **투명도 (설정 ⚙)**: 시험용 사이드바(원격 디버깅)로 계산된 화면 값을 확인했다. 불투명 = `rgb(27 47 42)`로 전과 같은 색, 70% = 배경만 `rgba(27 47 42 / .7)`이고 글씨·단추 색과 화면 전체 불투명도(1)는 그대로. 접으면 창이 6×84 포인트 노란 손잡이(55%)만 남는다. 펼친 동안은 `setIgnoreMouseEvents(false)`이고 배경이 0이 아니라(70%) 맥은 클릭을 사이드바가 받는다 — 선생님 눈 확인 남음.
23. **창 비키기를 맥에서도 켰다** (`ASIDE_OK`, 기본 꺼짐). 윈도우와 같은 공통 코드(`aside.js`, `Session.stepAside`·`restoreAside`)가 맥 도우미 `list`·`move`(포인트, 메뉴 막대를 뺀 사용 영역)로 그대로 동작한다. 시험이 직접 연 텍스트 편집기 창 하나만 보이게 걸러서 실제로 확인: (0,120, 700×400) → 비키기 (280,120, 480×400) → 돌려놓기 (0,120, 700×400). 맥은 `maximized`가 없어 초록 단추로 채운 창도 보통 창처럼 왼쪽만 당긴다.
24. 맥 도우미 `fullscreen`은 원래 맥 전체 화면(`AXFullScreen`)만 봤다. 파워포인트 슬라이드 쇼는 메뉴 막대까지 덮는 보통 창이라 놓칠 수 있어, 윈도우 도우미와 같이 "화면 전체를 덮는 창"도 전체 화면으로 알린다. 그래야 비키기가 슬라이드 쇼를 옮기지 않는다 (지금 열린 창 29개 중 잘못 잡힌 창 없음, 슬라이드 쇼로 직접 확인은 남음).
25. 사이드바가 두 개 켜져 있으면(개발용 + 설치판) 비키기가 다른 사이드바 창도 옮길 수 있다. 평소에는 하나만 켜므로 문제없지만, 시험할 때는 설치판을 끄고 한다.

## 답을 기다리는 창 — 저장 확인 창이 떠 있을 때 닫기 (4차, 2026-11-21)
`node runner/modal.js`(엑셀) · `node runner/modal.js --app=hwp`(한글). 예시 파일을 `poc/out/`에 새 이름으로 복사해 열고, 글자 하나를 넣은 뒤 닫기 요청을 보낸다. 선생님이 열어 둔 엑셀·한글 창은 건드리지 않았다. 외부 모니터 없이 맥 화면 하나로. 체험판(`app/`)도 실제로 띄워 같은 순서로 확인했다 (개발용 원격 조작, 임시 수업 폴더).

26. **맥의 답을 기다리는 창은 두 가지 모양이다.** 창에 붙는 시트(엑셀)와 프로그램 전체를 막는 모달 대화상자(한글, 엣지 로그인 창). 도우미 `list`가 창마다 `waiting`으로 알려 준다 (규격 `helper-protocol.md`). 모달 대화상자는 프로그램 전체를 막으므로 그 프로그램의 모든 창에 같은 `waiting`이 나온다. 최소화된 창도 하위 역할이 `AXDialog`이지만(→ 8) `AXModal`·최소화 여부로 구분된다.
27. **시트가 붙으면 프로그램의 "포커스 창"이 시트로 바뀐다.** 그래서 `front`가 시트 번호를 알려, 앞으로 가져오기가 1.5초를 기다린 뒤 실패로 판단했다. `front`가 바탕 창 번호 + `dialog`(시트)로 알리게 고쳤다 (윈도우 도우미와 같은 모양).
28. 한글은 바뀐 문서의 닫기 단추를 누르면 저장 창을 띄우느라 2.1초 뒤에 접근성 오류(-25204, 완료하지 못함)로 답한다. 요청은 전달됐으므로, 도우미는 창이 닫혔거나 `waiting`이 생겼으면 `ok: true`로 알린다. 바뀌지 않은 문서는 0.9초에 정상으로 닫힌다.
29. **한글은 저장 창이 떠 있어도 닫기 단추가 눌린다. 닫기를 또 보내면 저장 창이 하나 더 생기고, 그 창은 문서가 저장·닫힌 뒤에도 남아 선생님이 원래 열어 둔 한글 창까지 막았다.** (시험 도구가 만든 창이라 바로 "취소"로 치웠다.) → 체험판은 `waiting`이 있으면 닫기 요청을 보내지 않고 그 창을 앞으로 가져온다. 시험 도구는 정리할 때 대화상자를 모두 취소 → 닫기 한 번 → 저장 순서로 한다.
30. 한글은 바탕 창을 앞으로 가져오면(주 창으로 지정) 포커스가 대화상자에서 바탕 창으로 옮겨 간다. 도우미 `raise`가 이어서 대화상자에 포커스를 준다. 한글 대화상자는 화면 창 목록(CGWindow)의 "화면에 있음" 값이 처음부터 거짓이라 판단에 쓰지 않는다.
31. 지금 이 맥의 엣지에 모달 대화상자(로그인 창으로 보임)가 떠 있어 엣지 창 6개 모두 `waiting`이 나온다. 기록 5에서 엣지 창이 닫히지 않은 이유와 맞는다. 다른 프로그램(크롬·파워포인트·텍스트 편집기 등)은 `null`.
32. 한글의 말풍선 도움말(`AXHelpTag`)은 하위 역할이 없어 일반 창으로 목록에 섞여 들어왔다. 역할이 `AXWindow`인 것만 넣도록 고쳤다.
33. `list`는 창 28개에서 0.61초 → 0.66초 (창마다 시트 확인이 늘어남).
34. 시험 도구의 글자 입력은 `osascript`(JavaScript)로 키보드 이벤트를 보낸다. 손쉬운 사용 권한만 쓰고 "자동화" 권한 창은 뜨지 않았다. 키는 시험 창(또는 그 대화상자)이 맨 앞일 때만 보낸다. 시험 결과에 창 제목은 출력하지 않는다.
35. 텍스트 편집기는 시험하지 않았다 (엑셀·한글로 두 가지 모양을 모두 확인).
36. 윈도우 Claude의 `close()`(#14: 메모장 탭 보호, 1초쯤 뒤 앞으로 가져오기)와 하나로 합친 뒤 체험판으로 다시 확인: 엑셀 2.1초·한글 3.2초에 "답 기다림", 한글에 다시 ✕는 0.8초에 바로 표시되고 대화상자는 늘지 않음, 저장으로 답하자 두 자료 모두 "닫았습니다".

## 선생님 사용 중 문제 (2026-11-22, 설치판)
선생님 보고: ① 크롬을 열다 "프로필 문제" ② "창을 찾지 못했습니다 (30초)" ③ 창 비키기가 안 됨 ④ 창이 30개쯤 열림 ⑤ 다른 구글 계정으로 쓰던 유튜브가 로그아웃됨.

28. **원인(①②④⑤): 크롬이 켜진 채 업데이트를 받아 "다시 시작"을 기다리던 상태였다.** 켜진 크롬 157.0.8103.51, 디스크는 .79. 사이드바의 `open -na … --new-window`가 새 버전(.79) 크롬을 하나 더 띄웠고, 옛 버전이 쓰고 있는 같은 프로필을 열지 못해 "프로필 문제" → 그 크롬이 지난 창들을 되살려 창이 수십 개 → 사이드바는 짝지을 창을 못 찾아 30초 오류. 같은 프로필을 두 버전이 동시에 열어 로그인 정보(쿠키)가 풀린 것으로 보인다. 버전이 같을 때는 `open -na`가 켜진 크롬에 넘겨줘 문제없었다 (기술 검증 때).
    - 고침: 열기 전에 `browserState`로 켜진 브라우저 수와 버전(`lsof`의 `…Framework.framework/Versions/<버전>`, 디스크는 `Info.plist`)을 본다. 둘 이상 켜졌거나 버전이 다르면 **새로 띄우지 않고** `open -a <브라우저> <주소>`로 켜진 브라우저에 탭으로 열고 "다시 시작해 주세요"라고 알린다.
    - 남은 두 번째 크롬은 Claude가 끄려 했으나 막혀서(안전 확인) 선생님께 직접 끄도록 안내했다.
29. 열 때 브라우저 창이 여러 개 생기면 하나만 짝짓고 나머지는 "사이드바가 연 창"으로 기억한다. 사이드바 아래 **"사이드바가 연 창 모두 닫기"**(한 번 더 눌러야 실행)가 짝지은 창과 이 창들을 정상 닫기로 닫는다. 선생님이 원래 열어 둔 창은 건드리지 않는다 (④ "강제로 모두 닫기" 요청 — 강제 종료는 하지 않는다는 규칙에 맞춰 정상 닫기로).
30. ③ 창 비키기: 선생님 설정이 자동 숨김 켜짐이었다. 비키기는 사이드바를 고정했을 때만 동작하는데 안내가 잠깐 뜨고 사라져 몰랐다 → 설정 칸에 "지금은 자동 숨김이 켜져 있어 쉬고 있습니다" 안내를 계속 보인다.

31. **창 비키기를 맥에서는 "고정해 둔 동안 계속"으로 바꿨다** (선생님 두 번째 보고: 고정·설정을 켜 두었는데도 안 됨). 원래는 고정하는 순간에 한 번만 옮겨서, 고정해 둔 뒤 새로 열거나 왼쪽으로 옮긴 창은 가려진 채였다. 이제 맥은 고정해 둔 동안 2초마다 살펴 사이드바 아래로 들어온 창을 옮긴다 (`Session.keepAside`, `main.js` `ASIDE_KEEP`). 스스로 제자리로 돌아가는 프로그램과 밀고 당기지 않게 한 창은 1분에 3번까지. 돌려놓을 때는 처음 자리로. 시험이 연 창으로 확인: (0,150,700) → 280 → 선생님이 60으로 되돌림 → 다시 280 → 돌려놓기 (0,150,700).
32. 크롬을 다시 켠 뒤에도 "다시 시작 필요"가 계속 나온 까닭: 사이드바가 10:09에 잘못 띄운 두 번째 크롬(창 없음)이 남아 있었다. 선생님이 끈 것은 옛 버전 첫 번째 크롬이었고, 새로 켠 크롬까지 크롬이 둘이 됐다. 겹쳐 켜진 경우(`reason: 'two'`)와 업데이트 대기(`'update'`)를 나눠 안내하게 고쳤다 ("두 개 켜져 있음 · 모두 끈 뒤 다시 켜기, 남으면 활성 상태 보기에서 종료").

33. **선생님 세 번째 보고(창은 열리는데 "창을 찾지 못했습니다", 창 비키기 안 됨)의 원인은 손쉬운 사용 권한이 풀린 것으로 본다.** 오늘 설치판을 네 번 새로 깔았는데, 임시 서명이라 깔 때마다 맥은 다른 앱으로 본다. 설정 화면에는 "수업 사이드바"가 켜져 보여도 실제 권한은 풀려 있을 수 있고, 그러면 창 목록을 읽지 못해 창 찾기·비키기가 모두 안 된다. (맥 권한 기록·사이드바 화면은 Claude가 볼 수 없어 직접 확인은 못 함 — 두 증상이 함께 나고, Claude가 켠 같은 앱은 Claude의 권한으로 잘 됐음.) 고침: 5초마다 권한을 확인해 꺼져 있으면 사이드바 맨 위에 빨간 안내와 "손쉬운 사용 설정 열기" 단추를 계속 보이고, 권한이 없으면 30초를 기다리지 않고 바로 알린다. 권한이 켜지면 다시 켤 필요 없이 이어서 동작한다. 근본 해결: 매번 같은 서명으로 만들면 새로 깔아도 권한이 남는다 → 선생님이 키체인에서 자체 서명 인증서를 한 번 만들어 주셔야 한다 (`docs/PLAN.md` 10.1).

34. 선생님 네 번째 보고: 창 비키기를 켠 채로는 자동 숨김 단추가 듣지 않는 것 같다. 자동 숨김을 누르면 사이드바가 접히고 옮겼던 창이 돌아오지만 "창 비키기"는 켜진 채라 설정이 엇갈렸고, 2초마다 도는 비키기가 돌려놓는 사이에 창을 다시 옮길 수 있었다. → **자동 숨김을 켜면 창 비키기를 자동으로 끈다** (선생님 요청, 비키기 타이머를 먼저 멈춘 뒤 돌려놓음). 짝으로, 자동 숨김 중에 창 비키기를 켜면 사이드바를 자동으로 고정한다. 둘이 함께 켜질 일이 없어져 "쉬고 있습니다" 안내는 뺐다. (선생님 화면의 창을 옮기게 되므로 실제 사이드바로는 시험하지 않고 코드로 확인)

35. **같은 서명으로 만들기**: 선생님이 키체인 접근에서 자체 서명 코드 서명 인증서 "LessonSidebar Signing"을 만들었다 (신뢰 설정은 화면에서 못 바꿨지만 필요 없었다 — `codesign -s <인증서 번호>`는 "신뢰 안 함" 인증서로도 서명된다). 설치판을 만들 때 `build/sign-local.cjs`(electron-builder `afterSign`)가 이 인증서가 키체인에 있으면 다시 서명한다. 맥이 앱을 알아보는 기준이 `identifier "kr.lessonsidebar.app" and certificate leaf = H"…"`로 고정되어, 다음 설치부터는 손쉬운 사용 권한이 남는다. 인증서가 없는 곳(자동 검사)은 임시 서명 그대로.
