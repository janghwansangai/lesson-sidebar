- MacBook (Apple Silicon), macOS 27.2.1, Node 24.14, Swift 6.4
- 모니터: 내장 Retina 1512×982 포인트(배율 2, 주 모니터) + 외부 MB16NCG 1280×800 포인트(배율 2, 내장 화면 왼쪽)

## 알게 된 것 (설계에 반영)

1. **브라우저는 LaunchServices(`open -na <앱> --args --new-window <주소>`)로 연다.** 실행 파일을 직접 부르면 부른 프로그램의 제한을 물려받는다. 이번에는 시험 환경의 제한 때문에 엣지가 자기 설정 폴더를 만들지 못하고 바로 꺼졌다. `open`으로 열면 독립된 프로그램으로 실행되어 문제가 없다.
2. **로컬 파일을 `file://`로 브라우저에 넘기면 안 된다.** 엣지가 바탕화면 폴더의 시험 파일을 열려다 macOS의 "데스크탑 폴더의 파일에 접근하려고 합니다" 권한 창을 띄웠고, 답하기 전까지 빈 창이 됐다. 수업 중에 이런 창이 뜨면 곤란하다. 사이드바가 `127.0.0.1` 주소(무작위 토큰 포함, 수업 폴더만)로 파일을 제공하니 권한 창 없이 바로 열렸다. 학교 관리 브라우저가 `file://`을 막는 경우도 피할 수 있다.
3. **외부 모니터에도 메뉴 막대(30포인트)가 있는데 macOS가 사용 영역에서 빼 주지 않는다.** 그래서 창이 30포인트 아래로 밀렸다. 화면마다 떠 있는 메뉴 막대 창의 위치를 직접 읽어 사용 영역에서 빼도록 도우미를 고쳤다 (내장 33, 외부 30). "디스플레이마다 별도 공간 사용"이 꺼져 있어도 메뉴 막대가 보이는 상태였다.
4. **프로그램마다 최소 폭이 있다.** 크롬·엣지·웨일은 500포인트보다 좁아지지 않는다. 1280 폭 학생 화면에서 7:3을 고르면 오른쪽이 384가 되어 창이 겹친다. 조절 바와 배치 버튼은 최소 폭에서 멈추도록 비율을 조정한다 (`fitRatio`).
5. **프로그램에 확인·로그인 창(모달)이 떠 있으면 창 닫기 요청이 무시된다.** 엣지에 학교 Microsoft 계정 로그인 창이 떠 있어 다른 창이 닫히지 않았다. 사이드바는 "이 프로그램에 답을 기다리는 창이 있습니다"를 표시하고 그 창을 앞으로 가져와야 한다. 저장 여부를 묻는 창도 같다.
6. **브라우저 창 제목에 사용자 프로필 이름이 붙는다** (예: "… - Chrome - (프로필 이름)"). 창 제목을 공유 파일이나 기록에 남기지 않는다. 시험 결과 파일(`poc/out/`)은 저장소에 올리지 않는다.
7. 오피스 창 제목은 확장자 없는 파일 이름이다 ("샘플_발표자료"). 한글 파일 이름도 NFC/NFD 차이 없이 짝이 맞았다.
